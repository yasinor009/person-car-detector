# اجرای فاصله‌سنجی هندسی چندهدف — نسخه پژوهشی

مسیر CLI مستقل است. داشبورد app.py نیز با تنظیم CAMERA_GROUND_CALIBRATION
و CAMERA_LENS_CALIBRATION همین موتور چندهدف را فعال می‌کند؛ بدون این تنظیمات
مسیر قدیمی انتخاب تک‌هدف برقرار است. API /api/status تمام فیلدهای distance را
برای هر ID ارائه می‌دهد. رابط موجود فاصله و دلیل اعتبار را نشان می‌دهد.
این نسخه مدل عمق آموخته‌شده ندارد و پذیرش میدانی ۱۰۰ متر را تأیید نمی‌کند.
برای دوربین **ثابت** روی زمین **تخت**، فاصله هر ID از تقاطع پرتو نقطه پایین
کادر با صفحه زمین محاسبه می‌شود. خروجی فاصله اقلیدسی نقطه تماس است، نه مرکز خودرو.
گوشی دستی، شیب متغیر، انسداد پا/چرخ، هدف معلق و کادر غیرکامل این فرض را نقض می‌کنند.
تشخیص خودکار همه این نقض‌ها پیاده نشده؛ quality=conditional به همین دلیل است.

نصب Windows/Linux: Python 3.11 یا 3.12 و `python -m pip install -r requirements.txt`.
در Termux به بسته‌های سازگار Android برای numpy/OpenCV/ONNX Runtime نیاز است؛
wheel لینوکس قابل نصب مستقیم روی Android نیست. اجرای این نسخه روی گوشی هنوز آزمایش نشده.

مدل قابل تهیه و دارای هش تأییدشده موجود:

```sh
python download_optional_model.py
python run_metric.py --source video.mp4 --model models/visdrone26m_1280.onnx --output observations.jsonl --show
```

مدل فوق aerial و بزرگ است؛ صرفاً مسیر قابل اجرای موجود، نه انتخاب نهایی گوشی یا
مدل برنده دوربین زمینی. بدون کالیبراسیون همه فاصله‌ها null خواهند بود.
`--show` به محیط گرافیکی نیاز دارد؛ بدون آن خروجی JSONL headless تولید می‌شود.
فایل ویدئو بدون حذف فریم پردازش می‌شود؛ timestamp=index/FPS برای ویدئوی CFR است.
ویدئوی نرخ متغیر باید ابتدا با حفظ زمان‌بندی به CFR تبدیل شود.

ابتدا با `calibrate_lens.py` لنز را کالیبره کنید. فایل ground.json باید شامل
camera_matrix و image_size همان فایل لنز و موارد زیر باشد؛ مقادیر را **اندازه‌گیری**
کنید، از مثال عددی به‌عنوان کالیبراسیون واقعی استفاده نکنید:

| فیلد | تعریف |
|---|---|
| normal | بردار واحد عمود زمین به سمت پایین، در مختصات دوربین x راست، y پایین، z جلو |
| height_m | فاصله عمودی مرکز دوربین از صفحه زمین |
| height_std_m | انحراف معیار اندازه‌گیری ارتفاع |
| angle_std_deg | عدم‌قطعیت زاویه صفحه/دوربین برحسب درجه |
| pixel_std | انحراف معیار محل تماس در تصویر، از validation |
| systematic_relative_std | کف خطای نسبی سیستماتیک؛ باید از validation برآورد شود |
| calibration_id | شناسه یکتای کالیبراسیون و حالت دوربین |
| fixed_camera / planar_ground | هر دو true فقط اگر در برداشت برقرارند |

```sh
python run_metric.py --source video.mp4 --model models/visdrone26m_1280.onnx --lens data/lens.json --ground data/ground.json --output measured.jsonl --show
```

برای دوربین متصل source=0. اندازه ورودی باید دقیقاً برابر کالیبراسیون باشد؛
این مسیر از حدس crop/zoom خودداری می‌کند. فایل خروجی موجود بازنویسی نمی‌شود.
پراکندگی پیکسلی وارد نویز اندازه‌گیری Kalman می‌شود و خطای ارتفاع/زاویه/مدل
جداگانه به عدم‌قطعیت خروجی افزوده می‌شود. interval گاوسی فرضی است و پوشش تجربی
۹۵٪ تضمین نشده. معیار مهندسی رد: 1.96*std/range > 0.10 یا فاصله بیش از ۱۰۰ متر.
جهش بیش از سه انحراف معیار innovation رد می‌شود؛ مدل شتاب نیازمند tuning واقعی است.

ارزیابی: `python evaluate_range.py references.json --output report.json`.
فرمت input در docstring فایل توضیح داده شده است. هر هدف مرجع باید یک سطر داشته باشد؛
حتی هدفی که detector از دست داده با valid=false و prediction_m=null ثبت شود.
sequence/frame/object_id باید از annotation مستقل بیایند، نه تطبیق دلخواه برای کاهش خطا.
مرجع فاصله باید همان کمیت خروجی باشد. تمام binهای ۵ تا ۱۰۰ متر و دو کلاس گزارش
می‌شوند؛ bin خالی مقدار null دارد. خروجی accepted=false تا بررسی سایر معیارهای
تشخیص، Tracking، حجم نمونه، leakage و سخت‌افزار باقی می‌ماند.

قابلیت‌های باقی‌مانده: learned metric depth و mask، کالیبراسیون extrinsic خودکار،
ReID انسداد طولانی، AP/HOTA/IDF1 استاندارد، آموزش اختصاصی،
بنچمارک دستگاه و ارزیابی واقعی. هیچ‌کدام با تست مصنوعی تأیید نشده‌اند.
