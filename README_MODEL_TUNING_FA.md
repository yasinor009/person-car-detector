# راهنمای بهبود و ارزیابی مدل — نسخه ۲.۵

## چه چیزی در کد بهبود یافته است؟

- رمزگشایی خروجی خام YOLO به‌صورت برداری انجام می‌شود تا حلقهٔ Python روی ده‌ها هزار کاندید در هر فریم حذف شود.
- مدل ONNX هنگام راه‌اندازی یک استنتاج آزمایشی انجام می‌دهد؛ خروجی ناسازگار دیگر بی‌صدا به‌عنوان مدل آماده گزارش نمی‌شود.
- خطاهای استنتاج، شکل ورودی/خروجی، تعداد کاندیدها و زمان استنتاج در داشبورد نمایش داده می‌شوند.
- ورودی‌های NCHW و NHWC پشتیبانی می‌شوند.
- ردیابی دستی اندازهٔ ROI را با کادرهای کوچکِ تفاضل پس‌زمینه جایگزین نمی‌کند؛ این کار از جهش‌های مصنوعی در تخمین فاصله جلوگیری می‌کند.
- تشخیص حرکت برای ناحیه‌های کوچک حساس‌تر شده و حرکت کلی دوربین با تخمین affine مقاوم‌تر بررسی می‌شود.
- انتخاب روی تصویر از نسبت ابعاد واقعی فریم پیروی می‌کند.
- ابزار ارزیابی امکان جست‌وجوی آستانهٔ اطمینان را دارد.

## اسکن اختیاری اهداف کوچک/دور

مدل ورودی ثابتی با ابعاد ۴۱۶ دارد. اهداف خیلی کوچک ممکن است هنگام تغییر اندازهٔ کل تصویر از بین بروند. می‌توان حالت برش چهارناحیه‌ای را فعال کرد؛ اگر استنتاج تمام‌فریم چیزی پیدا نکند، چهار برش هم‌پوشان بررسی می‌شوند. این حالت ممکن است تا چهار استنتاج اضافی انجام دهد و روی گوشی کندتر و پرمصرف‌تر است.

```bash
cd ~/projects/drone_distance_delivery
export DRONE_TILED_INFERENCE=1
python main.py --browser-camera
```

برای غیرفعال‌کردن آن، سرور را متوقف و اجرا کنید:

```bash
unset DRONE_TILED_INFERENCE
python main.py --browser-camera
```

## ارزیابی واقعی دقت

مدل فعلی تک‌کلاسه است و برای پهپاد آموزش دیده؛ تشخیص حرکت عمومی فقط ناحیهٔ تغییر را پیدا می‌کند و آن را به‌عنوان انسان، خودرو یا حیوان طبقه‌بندی نمی‌کند.

برای اندازه‌گیری Precision، Recall و F1 باید مجموعه‌ای مستقل از تصاویر برچسب‌خورده تهیه شود. ساختار داده:

```text
dataset/
  images/
    scene01.jpg
    scene02.jpg
  labels/
    scene01.txt
    scene02.txt
```

هر خط فایل برچسب با قالب YOLO است: `class_id x_center y_center width height` با مقادیر نرمال‌شده بین ۰ و ۱. برای تصویر منفی، فایل `.txt` متناظر باید وجود داشته باشد و خالی باشد. کلاس پهپاد `0` است.

اجرای ارزیابی و جست‌وجوی آستانه:

```bash
python -m pip install pytest
python evaluate_detector.py --dataset /path/to/dataset --sweep --output evaluation_report.json
```

گزارش، آستانه‌ای را که روی همین مجموعه F1 بالاتری دارد پیشنهاد می‌کند. این آستانه را روی مجموعهٔ نهایی مستقل هم بررسی کنید؛ انتخاب آستانه روی همان داده‌ای که برای گزارش نهایی استفاده می‌شود، نتیجه را خوش‌بینانه می‌کند.

## برای رسیدن به دقت بالای ۸۰٪ چه چیز دیگری لازم است؟

1. آزمون مستقل از شرایط واقعی گوشی: آسمان روشن/ابری، پس‌زمینه‌های شلوغ، فاصله‌های مختلف، اهداف کوچک، پرنده‌ها و تصاویر بدون پهپاد.
2. برچسب‌های دقیق برای هر فریم آزمون و اندازه‌گیری Precision، Recall، F1 و mAP در IoU مشخص.
3. اگر ارزیابی نشان داد خطا از خود وزن‌هاست، دادهٔ آموزشی برچسب‌خورده و وزن قابل‌آموزش (`.pt`) برای بازآموزی یا fine-tuning لازم است. فایل ONNX فعلی برای استنتاج است و به‌تنهایی وزن آموزشی قابل fine-tune نیست.
4. اجرای مجدد ارزیابی پس از هر تغییر و گزارش نتیجه روی مجموعهٔ آزمون نگه‌داشته‌شده.

**محدودیت:** این نسخه کد استنتاج، ردیابی و ارزیابی را بهبود می‌دهد؛ چون مجموعهٔ آموزشی/آزمون برچسب‌خوردهٔ کاربر و فایل وزن آموزشی در بسته موجود نیست، ادعای دقت بالای ۸۰٪ یا بهبود عددی دقت مدل قابل تأیید نیست. مدل وزن‌دار از مخزن عمومی نصب‌کننده دریافت می‌شود و دقت گزارش‌شدهٔ ناشر معادل دقت تضمین‌شده روی دوربین گوشی نیست.
