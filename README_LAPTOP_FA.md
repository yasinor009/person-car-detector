# نسخهٔ آزمایشی لپ‌تاپ — وضعیت هدف هنوز «تأییدنشده» است

این نسخه برای سیستم اعلام‌شدهٔ شما، CPU i3-10100، رم ۱۶ گیگابایت و VRAM اعلام‌شدهٔ ۶ گیگابایت، آمادهٔ آزمون شده است. نام کارت گرافیک، سیستم‌عامل و مشخصات دوربین هنوز معلوم نیست. VRAM به‌تنهایی مشخص نمی‌کند CUDA در دسترس است. سرعت روی دستگاه شما اندازه‌گیری نشده است.

**هدف خواسته‌شده: Precision و Recall هرکدام حداقل ۹۰٪ برای هر دو کلاس انسان و خودرو، از جمله آزمون مستقل با فاصلهٔ واقعی حداقل ۱۵۰ متر. این هدف هنوز محقق/اثبات نشده است.** آستانهٔ اطمینان ۰٫۹، معادل دقت ۹۰٪ نیست.

## نصب در ویندوز

۱. فایل را کامل استخراج کن. Python نسخهٔ ۳٫۱۱ یا ۳٫۱۲ از python.org نصب باشد.
۲. داخل پوشهٔ پروژه، `install_laptop.bat` را اجرا کن. محیط مجزای `.venv` ساخته می‌شود و بسته‌های CPU نصب می‌شوند. مدل‌های اصلی داخل بسته‌اند؛ نصب بسته‌ها اینترنت می‌خواهد.
۳. `start_laptop.bat` را اجرا کن.
۴. وقتی سرور شروع شد، در مرورگر **همان لپ‌تاپ** آدرس `http://127.0.0.1:5000` را باز کن و شروع تشخیص را بزن.

این آدرس فرمان CMD نیست. پنجرهٔ اجرای برنامه را باز نگه دار. پیش‌فرض از دوربین شمارهٔ صفر لپ‌تاپ/USB استفاده می‌کند. دوربین را سیستم‌عامل و OpenCV باید بشناسند. برای دوربین شمارهٔ یک در CMD داخل پوشه:

```bat
.venv\Scripts\python run_laptop.py --profile balanced --source 1
```

برای دوربین تحت شبکه یا ویدئو:

```bat
.venv\Scripts\python run_laptop.py --profile balanced --source "rtsp://CAMERA_ADDRESS/STREAM"
.venv\Scripts\python run_laptop.py --profile balanced --source "D:\videos\test.mp4"
```

برای استفاده از دوربین مرورگر به‌جای OpenCV:

```bat
.venv\Scripts\python run_laptop.py --profile balanced --browser-camera
```

در حالت‌های برش، درخواست رزولوشن USB هم به‌طور پیش‌فرض تا ۳۸۴۰×۲۱۶۰ است؛ در balanced برابر ۱۹۲۰×۱۰۸۰ است. با `--capture-width` و `--capture-height` قابل‌تغییر است؛ اندازهٔ واقعی دریافت‌شده در وضعیت تصویر منبع نشان داده می‌شود. شبکهٔ RTSP/فایل باید خودش stream مناسب را ارائه کند و این درخواست ابعاد وب‌کم روی آن اعمال نمی‌شود.

در حالت مرورگر هم درخواست تصویر تا 4K است و کوچک‌سازی اجباریِ قبلی به عرض ۹۶۰ پیکسل حذف شده؛ رزولوشن واقعی به دوربین، مرورگر و مجوزها بستگی دارد. یک وب‌کم ۷۲۰p با درخواست 4K واقعاً 4K نمی‌شود. JPEG با کیفیت بالاتر ارسال می‌شود. حالت مستقیم USB/RTSP برای آزمون سرعت و جزئیات ترجیح دارد؛ مرورگر ممکن است هزینهٔ فشرده‌سازی/انتقال اضافه کند.

## فعال‌کردن NVIDIA، اختیاری

ابتدا `diagnose_laptop.py` را اجرا کن:

```bat
.venv\Scripts\python diagnose_laptop.py
```

اگر کارت NVIDIA و درایور سازگار داری، `install_nvidia.bat` را اجرا کن؛ این فرمان ONNX Runtime نسخهٔ GPU و وابستگی‌های CUDA/cuDNN را در همان `.venv` نصب می‌کند. درایور NVIDIA را خودکار نصب/تغییر نمی‌دهد. روی کارت‌های قدیمی یا درایورهای ناسازگار ممکن است نسخهٔ سازگار دیگری لازم باشد؛ نام دقیق GPU و خطای اجرا را باید بررسی کرد.

پس از اجرا، باید در وضعیت برنامه `cuda:0` و `CUDAExecutionProvider` دیده شود. وجود شش گیگابایت حافظه یا صرف نصب بسته، اثبات اجرای GPU نیست. برای درخواست صریح GPU:

```bat
.venv\Scripts\python run_laptop.py --profile balanced --device cuda:0
```

اگر GPU در دسترس نباشد، این درخواست با خطا متوقف می‌شود؛ اجرای CPU به‌جای GPU با نام جعلی گزارش نمی‌شود. برای CPU:

```bat
.venv\Scripts\python run_laptop.py --profile cpu --device cpu
```

## پروفایل‌ها

| پروفایل | مدل/رفتار | کاربرد و محدودیت |
|---|---|---|
| `balanced` | YOLO26s عمومی، ورودی پیش‌فرض ۹۶۰، تصویر کامل | شروع مناسب برای دوربین زمینی؛ روی دوربین شما اعتبارسنجی نشده است. |
| `cpu` | YOLO26n عمومی | سبک‌تر؛ برای اهداف خیلی کوچک افت recall ممکن است زیاد باشد. |
| `long-range` | مدل عمومی با ورودی پیش‌فرض ۱۲۸۰ و برش‌های هم‌پوشان | جزئیات بیشتری از هدف دور به شبکه می‌رساند؛ تضمین ۱۵۰ متر نیست و هزینهٔ بیشتری دارد. |
| `aerial` | مدل YOLO11s آموزش‌دیده توسط منتشرکننده روی VisDrone، ۱۲۸۰ و برش | مناسب بررسی نماهای هوایی/مرتفع؛ برتری آن به دوربین زمینی تعمیم داده نمی‌شود. |
| `accuracy-aerial` | YOLO26m هوایی، وزن بزرگ‌ترِ اختیاری | کیفیت بالاتر در برخی آزمون‌های هوایی، ولی کندتر؛ باید جدا دانلود و روی GPU/دوربین آزمایش شود. |

برای حالت برش:

```bat
.venv\Scripts\python run_laptop.py --profile long-range --device cuda:0
```

برای نماهای هوایی، `start_aerial.bat` یا:

```bat
.venv\Scripts\python run_laptop.py --profile aerial --device cuda:0
```

مدل بزرگ‌تر اختیاری، با checksum همان فایلی که آزموده شد:

```bat
.venv\Scripts\python download_optional_model.py
.venv\Scripts\python run_laptop.py --profile accuracy-aerial --device cuda:0
```

برش‌ها اندازهٔ ثابت در پیکسل منبع دارند، نه فقط چهار تکهٔ نسبی؛ تصویر کامل هم پردازش می‌شود. مختصات به تصویر اصلی برمی‌گردد، کادرهای قطع‌شده در مرز داخلی برش کنار گذاشته می‌شوند و NMS جدا برای هر کلاس انجام می‌شود. همهٔ نواحی پوشش داده می‌شوند؛ اگر تعداد برش از حد تعیین‌شده بیشتر شود، برنامه خطا می‌دهد و بخشی از تصویر را بی‌صدا حذف نمی‌کند.

پیش‌فرض batch=1 برای کنترل حافظهٔ شش‌گیگابایتی است. مدل‌های ONNX با batch پویا از `--batch 2` پشتیبانی می‌کنند؛ مدل ثابت batch-one برش‌ها را جدا اجرا می‌کند. این گزینه برای آن مدل ثابت، شتاب batch ایجاد نمی‌کند. با خطای کمبود حافظه به batch=1 و مدل کوچک‌تر برگرد. سرعت ۱۰ یا ۳۰ FPS برای GPU شما ادعا نشده است.

## چرا ۱۵۰ متر بدون مشخصات دوربین قابل‌تضمین نیست؟

یک مثال محاسباتی، نه دوربین شما: تصویر ۱۹۲۰×۱۰۸۰، میدان دید افقی ۶۰ درجه، انسان روبه‌دوربین با ارتفاع ۱٫۷ متر و عرض ۰٫۵ متر در ۱۵۰ متر. تصویر هدف حدود **۱۹ پیکسل ارتفاع و ۵٫۵ پیکسل عرض** دارد. کوچک‌سازی تمام تصویر به عرض ۶۴۰، آن را حدود **۶ پیکسل ارتفاع و ۱٫۸ پیکسل عرض** می‌کند. برش، اطلاعات موجود را بهتر حفظ می‌کند؛ اطلاعاتی که لنز/حسگر ثبت نکرده‌اند را ایجاد نمی‌کند.

```bat
.venv\Scripts\python optics_check.py --width 1920 --height 1080 --hfov 60 --distance 150
```

میدان دید واقعی/فاصلهٔ کانونی، فوکوس، حرکت، لرزش، نور، هوای مه‌آلود، پوشیدگی و ابعاد هدف لازم‌اند. زوم دیجیتال به‌تنهایی جزئیات اپتیکی اضافه نمی‌کند. تشخیص هدف کوچک روی VisDrone به معنی اثبات فاصلهٔ ۱۵۰ متر نیست؛ آن مجموعه برچسب فاصلهٔ واقعی این هدف را برای این آزمون ندارد.

## فاصلهٔ عددی

قواعد نسخهٔ قبل باقی‌اند: دوربین باید کالیبره و عرض واقعی همان هدف معلوم باشد. عدد، تخمین عمقِ محور نوری است؛ اندازه‌گیری LiDAR نیست. هدف بریده، گم‌شده یا با عرض کمتر از ۱۲ پیکسل، فاصلهٔ معتبر نمی‌گیرد. برای انسان ۱۵۰متری با عرض حدود ۵ پیکسل در مثال بالا، این نسخه عمداً فاصلهٔ دقیقِ ساختگی نمایش نمی‌دهد.

فایل تنظیمات/کالیبراسیون به وزن مدل، پروفایل، منبع دوربین و فایل اصلاح لنز وابسته شده تا کالیبراسیون قبلی بی‌دلیل برای حالت دیگر استفاده نشود. با تغییر زوم، برش یا حالت دوربین دوباره کالیبره کن.

## سنجش هدف ۹۰/۹۰

ساختار مجموعهٔ آزمون:

```text
test_set/
  images/
  labels/
  ranges.json     (فقط اگر فاصله‌ها واقعاً مستقل اندازه گرفته شده‌اند)
```

برچسب YOLO استاندارد با پنج ستون است. با `--label-schema two-class` انسان صفر و خودرو یک است؛ با `coco` انسان صفر و خودرو دو. تصاویر منفیِ دیوار، سایه، پوستر و بازتاب باید فایل برچسب خالی داشته باشند. تمام اهداف واقعی باید صحیح برچسب بخورند، حتی هدف‌های سخت و کوچک. هیچ تصویر یا هدف سختی فقط برای بالابردن نتیجه حذف نمی‌شود.

ابتدا آستانه‌ها را روی **validation جدا** انتخاب کن:

```bat
.venv\Scripts\python tune_laptop.py --dataset camera_data\val --split validation --label-schema two-class --model models\person_car_yolo26s.onnx --device cuda:0 --output validation\thresholds.json
```

اگر هدف ۹۰/۹۰ برای هر دو کلاس پیدا نشود، گزارش `target_met=false` و کد خروجی ۲ می‌دهد. آستانهٔ پیشنهادیِ آن حالت فقط برای بررسی است، نه تأیید دقت. بعد آستانه‌ها را ثابت کن و روی test مستقل اجرا کن:

```bat
.venv\Scripts\python evaluate_laptop.py --dataset camera_data\test --split test --label-schema two-class --model models\person_car_yolo26s.onnx --device cuda:0 --thresholds validation\thresholds.json --output validation\camera_test.json
```

برای پذیرش، هر دو معیار در هر دو کلاس باید به هدف برسند و حداقل ۵۰ هدف از هر کلاس موجود باشد. این حد، پیش‌فرض مهندسی برای جلوگیری از ادعای بزرگ با دو عکس است؛ حتی ۵۰ نمونه هم تضمین تعمیم آماری نیست. معیار مکان‌یابی IoU≥۰٫۵ است. گزارش، count واقعی TP/FP/FN و کران Wilson برای precision را دارد؛ فریم‌های نزدیک و هم‌بسته را نباید نمونه‌های مستقل شمرد.

برای بخش ۱۵۰ متر، `ranges.json` فقط صحنه‌هایی را فهرست کند که **تمام اهداف آنها** با روش مستقل در حداقل ۱۵۰ متر تأیید شده‌اند:

```json
{"verified_minimum_range_m":150,"method":"اندازه‌گیری مستقل با فاصله‌یاب یا نقشه‌برداری صحنه","images":["far_scene_01.jpg","far_scene_02.jpg"]}
```

این مثال را با اندازه‌گیری واقعی پر کن؛ از فاصلهٔ تخمینی مدل یا کوچک‌بودن کادر برای ساخت این فایل استفاده نکن. حداقل نمونه برای بخش دور هم لازم است. بدون این شواهد، بخش ۱۵۰ متر تأیید نمی‌شود. ارزیاب تصویر مستقل، کیفیت ردیابی ویدئو را نمی‌سنجد.

دروازهٔ پذیرش علاوه بر دقت، هدف آزمایشی سرعت استنتاج حداقل ۱۰ FPS را بررسی می‌کند؛ این عدد هدف مهندسی اولیه است و توسط شما به‌عنوان عدد دقیق درخواست نشده بود. سرعت کامل دوربین/مرورگر ممکن است کمتر باشد. گزارش CPU این محیط به i3/GPU شما تعمیم داده نمی‌شود. با شکست هر شرط، `acceptance.passed=false` و کد خروجی ۲ ثبت می‌شود.

## آموزش اختصاصی برای ادامهٔ رسیدن به هدف

دادهٔ واقعیِ دوربین لازم است. ویدئوها را بر اساس محل/زمان ضبط به train، val و test جدا کن؛ فریم‌های مجاور را بین بخش‌ها پخش نکن. هر بخش `images` و `labels` با کلاس‌های صفر=انسان، یک=خودرو داشته باشد. نمونهٔ واقعیِ روز/شب، فاصله‌های مختلف، اهداف دور و تصاویر منفی دیوار لازم‌اند. تعداد ثابتِ عکس، دقت ۹۰٪ را تضمین نمی‌کند.

برای ممیزی اولیه، پس از نصب بسته‌های آموزش:

```bat
.venv\Scripts\python -m pip install -r requirements-training.txt
.venv\Scripts\python train_two_class.py --dataset camera_data --audit-only
```

PyTorch باید با کارت و درایور شما سازگار باشد. برای شروع محافظه‌کارانه روی VRAM شش گیگابایت:

```bat
.venv\Scripts\python train_two_class.py --dataset camera_data --model yolo26s.pt --imgsz 1280 --batch 1 --epochs 100 --device 0
```

در این جلسه آموزش روی دادهٔ شما انجام نشده است. ابزار، تکرار دقیق تصویر بین بخش‌ها، برچسب نامعتبر و فقدان یکی از کلاس‌ها را رد می‌کند؛ تشابه فریم‌ها و تقسیم بر اساس صحنه همچنان باید جدا بررسی شوند. خروجی آموزش/ONNX به‌تنهایی قبولی ۹۰/۹۰ نیست؛ تنظیم آستانه و آزمون مستقل بعدی لازم است.

## آزمون‌ها و شواهد

۸۱ آزمون نرم‌افزار موفق بوده‌اند؛ این عدد به معنی دقت ۸۰٪ یا اثبات دقت مدل نیست.

```bat
.venv\Scripts\python -m pip install -r requirements-test.txt
.venv\Scripts\python -m pytest -q
```

گزارش مقایسهٔ مدل‌ها: `LAPTOP_EXPERIMENTS_FA.md`.
منابع و تصمیم‌های پژوهشی: `LAPTOP_RESEARCH_FA.md`.
فایل وضعیت صریح هدف: `ACCEPTANCE_STATUS.json`.
وزن‌ها، منبع، نگاشت کلاس و checksum: `models/PROVENANCE_V4.json`.

مدل‌های عمومی COCO و مدل‌های هوایی VisDrone در داخل کلاس‌های بیشتری دارند؛ خروجی مجاز فقط انسان و خودرو است. مدل دوکلاسهٔ آموزش‌دیدهٔ خودتان نیز با نام کلاس صحیح قابل‌بارگذاری است. کامیون، اتوبوس، ون و موتورسیکلت به خودرو تبدیل نمی‌شوند. در ارزیابی VisDrone، pedestrian و people به انسان، و car به خودرو نگاشت شده‌اند؛ سایر کلاس‌ها هدف نیستند.
