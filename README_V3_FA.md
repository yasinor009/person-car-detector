# نسخهٔ ۳: تشخیص انسان و خودرو و تخمین فاصله

این راهنما جایگزین دستورالعمل‌های نسخه‌های ۲ است. فقط خروجی انسان (`person`، کلاس COCO صفر) و خودروی سواری (`car`، کلاس COCO دو) فعال است؛ اتوبوس، کامیون، موتورسیکلت و سایر کلاس‌ها نمایش داده نمی‌شوند. مدل در داخل ۸۰ کلاس COCO را بررسی می‌کند و سپس فقط این دو کلاس را می‌پذیرد؛ وزن‌ها مدل تخصصی آموزش‌دیده روی دوربین شما نیستند.

## اجرا روی Termux

فایل را کامل استخراج کن؛ هر دو مدل داخل پوشهٔ models هستند و نصب‌کننده دیگر مدل قدیمی پهپاد را دانلود نمی‌کند:

```bash
bash install_termux.sh
python main.py --browser-camera
```

در مرورگر همان گوشی `http://127.0.0.1:5000` را باز کن، دوربین پشتی را فعال کن و اجازهٔ دسترسی بده. نصب‌کننده به اینترنت برای بسته‌های Termux نیاز دارد. اجرای تشخیص بعد از نصب به اینترنت نیاز ندارد. دسترس‌پذیری بسته‌های OpenCV و ONNX Runtime به مخزن و معماری Termux وابسته است؛ نصب باید روی گوشی واقعی بررسی شود.

حالت سبک پیش‌فرض YOLO11n با ورودی ۶۴۰ است. برای مدل بزرگ‌تر YOLO11s:

```bash
python main.py --browser-camera --model models/person_car_yolo11s.onnx
```

مدل بزرگ‌تر در ارزیابی عمومی COCO دقت بیشتری دارد ولی کندتر است؛ انتخاب بهتر برای گوشی شما به سرعت، گرما و تصاویر واقعی بستگی دارد. با `--demo` فقط دادهٔ مصنوعی برای بررسی رابط ساخته می‌شود؛ این حالت آزمون تشخیص واقعی نیست.

## کاهش خطای کاذب

- آستانهٔ پیش‌فرض ۰٫۶۰ است؛ حداقل مؤثر ۰٫۵۵ است حتی اگر عدد کوچک‌تری در تنظیمات ثبت شود. این اعداد نقطهٔ شروع هستند، نه آستانهٔ بهینهٔ اندازه‌گیری‌شده برای محیط شما.
- برندهٔ کلاس ابتدا بین تمام ۸۰ کلاس انتخاب می‌شود تا مثلاً اتوبوس با نمرهٔ فرعی انسان، انسان نام‌گذاری نشود.
- حذف کادر تکراری برای هر کلاس جدا انجام می‌شود؛ انسان کنار خودرو یکدیگر را حذف نمی‌کنند.
- تطبیق یک‌به‌یک IoU و تأیید در سه فریم متوالی پیش از نمایش انجام می‌شود. شناسهٔ track یک شناسهٔ موقت است و هویت شخص نیست.
- حرکت، سایه، بافت دیوار و لکهٔ گرم دیگر مستقیماً کادر تشخیص نمی‌سازند. نبود مدل به معنی توقف تشخیص است.
- نبود مشاهدهٔ تازه به معنی حذف کادر است. مدل هنوز ممکن است دیوار یا تصویر انسان روی پوستر را اشتباه تشخیص دهد؛ هیچ مدل عمومی تضمین خطای صفر ندارد. این تنظیم محافظه‌کارانه ممکن است برخی اهداف کوچک، سریع یا پوشیده را از دست بدهد.

## فاصله

۱. پس از پایدارشدن کادر انسان یا خودرو روی آن بزن. کشیدن کادر فقط وقتی پذیرفته می‌شود که با یک تشخیص تأییدشده هم‌پوشانی کافی داشته باشد؛ دیوار با کشیدن کادر، خودرو نمی‌شود.
۲. عرض واقعی همان هدف را برحسب متر وارد کن. عرض پیش‌فرض و یکسان برای همهٔ انسان‌ها یا خودروها وجود ندارد.
۳. هدف مرجع با عرض معلوم را در فاصلهٔ اندازه‌گیری‌شده قرار بده و کالیبراسیون هدف منتخب را انجام بده. دوربین و مرجع را ثابت نگه دار.
۴. برای هدف جدید دوباره عرض واقعی همان هدف را ثبت کن؛ کالیبراسیون دوربین فقط تا وقتی دوربین، لنز، زوم، برش و حالت تصویر ثابت‌اند معتبر است.

فرمول `Z = fx * W / w` عمق در راستای محور نوری دوربین را تخمین می‌زند. این عدد فاصلهٔ لیزری یا فاصلهٔ اقلیدسی دوربین تا نقطهٔ خارج از محور نیست. لباس، زاویهٔ بدن یا خودرو، پوشیدگی، خطای کادر، فوکوس و اعوجاج روی نتیجه اثر دارند. برای عرض دو برابر با همان کادر، فاصلهٔ تخمینی دو برابر می‌شود؛ اندازهٔ واقعی را نمی‌توان از یک عکس عمومی با قطعیت بازیابی کرد. برای اندازه‌گیری مطلق دقیق‌تر باید حسگر عمق، استریوی کالیبره، LiDAR یا مرجع اندازهٔ قابل اعتماد استفاده شود.

فاصلهٔ هدف گم‌شده یا کادر کمتر از ۱۲ پیکسل یا کادر بریده در لبهٔ تصویر معتبر نمایش داده نمی‌شود. تغییر رزولوشنِ ساده با مقیاس‌دهی فاصلهٔ کانونی پوشش داده می‌شود؛ تغییر زوم یا برش نیاز به کالیبراسیون مجدد دارد. تغییر مدل هم می‌تواند حدود کادرها را تغییر بدهد؛ بعد از تعویض مدل کالیبره کن. فایل تنظیمات v2 را به نسخهٔ جدید منتقل نکن.

### کالیبراسیون چنداندازه‌گیری

حداقل پنج مشاهدهٔ مستقل در فاصله‌های مختلف تهیه کن. ترجیحاً ۱۰ تا ۲۰ مشاهده با مرجع ثابت و روبه‌دوربین بگیر. فرمت `samples.json`:

```json
[
  {"known_width_m":0.5,"known_distance_m":2,"observed_width_px":250,"frame_width_px":640},
  {"known_width_m":0.5,"known_distance_m":3,"observed_width_px":166.67,"frame_width_px":640},
  {"known_width_m":0.5,"known_distance_m":4,"observed_width_px":125,"frame_width_px":640},
  {"known_width_m":0.5,"known_distance_m":5,"observed_width_px":100,"frame_width_px":640},
  {"known_width_m":0.5,"known_distance_m":6,"observed_width_px":83.33,"frame_width_px":640}
]
```

این اعداد فقط مثال محاسباتی‌اند؛ با اندازه‌گیری واقعی جایگزین کن. برنامه را ببند و اجرا کن:

```bash
python calibrate_multiview.py samples.json
python calibrate_multiview.py samples.json --apply
```

میانه و MAD برای حذف دادهٔ پرت استفاده می‌شوند؛ حداقل پنج نمونهٔ پذیرفته‌شده و حداقل ۷۰٪ توافق لازم است. پراکندگی بالاتر از ۸٪ رد می‌شود. این مقدار عدم‌قطعیت واقعی فاصله را تضمین نمی‌کند؛ خطای سیستماتیک در همهٔ مشاهدات ممکن است باقی بماند. بعد از اجرا برنامه را باز کن، هدف را انتخاب کن و عرض واقعی همان هدف را وارد کن.

### اصلاح اعوجاج لنز، اختیاری

با همان دوربین، نسبت تصویر و زوم، دست‌کم ده عکس از صفحهٔ شطرنجی تخت در موقعیت‌ها و زاویه‌های مختلف تهیه کن. `cols` و `rows` تعداد گوشه‌های داخلی هستند؛ `square-m` طول ضلع هر خانه به متر است:

```bash
python calibrate_lens.py chessboard_photos --cols 9 --rows 6 --square-m 0.025
CAMERA_LENS_CALIBRATION=data/lens.json python main.py --browser-camera
```

اصلاح لنز روی همان تصویرِ تشخیص و نمایش اجرا می‌شود. نگاشت اصلاح برای کاهش هزینهٔ CPU کش می‌شود. نسبت تصویر ناسازگار رد می‌شود؛ روی تصویر اصلاح‌شده دوباره کالیبراسیون فاصله انجام بده. RMS بازفرافکنی زیر یک پیکسل، شرط پذیرش اولیه است و تضمین صحت سراسری لنز نیست.

## سنجش واقعی

```bash
python -m pip install -r requirements-test.txt
python -m pytest -q
python evaluate_detector.py --dataset my_test_data --conf 0.60 --output evaluation.json
python evaluate_detector.py --dataset my_validation_data --sweep --output tuning.json
```

ساختار مجموعه `images/...jpg` و `labels/...txt` با برچسب YOLO است. شناسه‌ها باید COCO باشند: انسان ۰، خودرو ۲؛ برای دیوار و صحنهٔ فاقد هدف، فایل برچسب خالی لازم است. اگر دیتاست اختصاصی کلاس خودرو را ۱ نوشته، پیش از ارزیابی به ۲ تبدیل کن. تطبیق کادر و کلاس هردو لازم است. ارزیابی تصویر مستقل بدون تأیید سه‌فریمی اجرا می‌شود؛ نتیجه کیفیت ردیابی ویدئو را نمی‌سنجد. آستانه را با validation انتخاب کن و نتیجه را روی test جدا گزارش کن.

این بسته روی دادهٔ شما آموزش مجدد ندیده و درصد دقت، FPS گوشی یا خطای متری میدان واقعی برای آن ادعا نشده است. برای بهترشدن تشخیص دیوار، تصاویر منفی واقعی از همان محل با نورهای مختلف را وارد مجموعهٔ اعتبارسنجی و در مرحلهٔ آموزش تخصصی وارد دادهٔ آموزشی کن. ویدئوهای مجاور را بین train و test تقسیم نکن؛ محل‌ها و ویدئوهای مستقل انتخاب کن.

آزمون‌ها، منطق نرم‌افزار و بارگذاری مدل را بررسی می‌کنند؛ نتیجهٔ نمونه‌ها در `VALIDATION_REPORT_FA.md` آمده است. وزن‌ها و مجوز در `models/PROVENANCE.json` و `models/ULTRALYTICS_LICENSE.txt` ثبت شده‌اند.
